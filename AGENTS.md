# ClaudeMods

A monorepo of Claude Code mods (function-hook plugins) that doubles as a plugin marketplace.

## Structure

- `.claude-plugin/marketplace.json` lists every mod; adding, renaming or removing a mod folder means updating this list and the table in `README.md`.
- Each mod is a self-contained folder at the root, with its own `AGENTS.md` and `README.md`.
- `tools/ModTesting.psm1` drives mods in a real Claude Code session for testing (Windows only).
- `**/.claude-plugin/types/` is generated by Claude Code when it loads a mod from a watched folder and is never committed.

## Conventions

- Code, comments and documentation are in English.
- Source files follow `.editorconfig` (tabs for `.ts`, `.tsx`, `.json` and PowerShell files).
- A mod's one-line description stays identical in its `plugin.json`, its `marketplace.json` entry and the `README.md` table.
- Commits follow Conventional Commits, scoped by mod folder (for example `feat(status-bar): ...`).

## Checks

Run before committing, from the repository root:

- `claude plugin validate .` validates the marketplace manifest.
- `claude plugin validate <mod>` validates a mod's manifest and hooks module against the engine's scan.
- `claude plugin test <mod>` runs a mod's test suites.

## Testing in a live session

Changes that affect drawing (layout, colors, panes, clicks) are verified in a real session, without the user, through `tools/ModTesting.psm1`:

- `Start-ModTestSession -PluginDirectory <mod> -WorkingDirectory <folder> -Fullscreen` opens a new terminal window running Claude Code with the mod loaded and returns the session; `-Fullscreen` uses the renderer where panes dock beside the transcript, and `-Columns`/`-Rows` size the window.
- `Save-ModTestCapture -Session $session -Path <png>` captures the window; read the image to check the result and to find click coordinates.
- `Invoke-ModTestClick -Session $session -X <x> -Y <y>` clicks a point of the window, in the capture's pixels.
- `Send-ModTestKey -Session $session -Keys <keys>` types into the session, in `SendKeys` notation (`+{TAB}` cycles the permission mode, `Foo{ENTER}` submits a prompt).
- `Stop-ModTestSession -Session $session` stops the session and closes its window.

Rules for live testing:

- Wait about 15 seconds after starting a session before the first capture, and about 2 seconds after each click or key.
- The session starts with a clean environment, so it runs as a regular session even when started from inside another one; never use `--resume` on the session doing the work.
- A submitted prompt spends real usage: keep it to a minimal one (`Reply with the single word ok`) and only when the check needs model output.
- A mod loaded with `--plugin-dir` reloads when its files are saved, so a fix can be checked in the same session.
- Captures may show account details: keep them in a temporary folder, never in the repository, and delete them when done.
